# Project_Godeok — 영양소 검출 배틀로얄

중2 과학 「Ⅵ. 동물과 에너지 ─ 1. 소화와 순환 · 01 영양소」 수업용 **3인칭 멀티플레이 슈팅 웹게임**.
작년 언리얼 버전(필드에서 시약을 줍고 음료에 다가가면 반응)을 배틀그라운드식 슈팅으로 다시 만든 것.

* 필드 : 컨테이너 야드 + **모둠 창고 8동(들어갈 수 있고, 안쪽 계단으로 옥상까지)** + 마을이 있는 섬
  (**반지름 198m · 32명 기준으로 넓힘**)
* 미지의 음료 : 거대한 비커 **6개 = A·B·C 두 세트**(제1·제2 실험장). 같은 글자면 같은 음료
* **음료 24종 중 라운드마다 후보 8종만** 뽑고, 지난 판 정답은 다시 안 나옵니다 (연속 3판 해도 안 겹침)
* 시약 4종을 주워 **탄알로 장전 → 비커에 사격 → 색 반응 확인**
* **★ 베네딕트는 가열해야 반응합니다.** 필드의 🔥 가열대에 다가가 몸을 데운 뒤 쏴야 합니다
* **4명 1팀**, 최대 8모둠(32명). 다른 모둠에게 **마취탄 3발**을 맞으면 30초 정지
* **순위 = 음료 3개를 먼저 다 맞힌 순서.** 🥉 **3등이 나오면 라운드가 자동으로 끝나고 정산**됩니다
* **접속하면 전원이 「대기 공간」에서 조작 연습** → 선생님이 [게임 시작]을 누르면
  **전원이 동시에** 각자 모둠 창고로 리스폰
* **모둠 창고 = 안전구역.** 정답은 안전구역 안에서만 제출할 수 있고, 그 안에서는 마취탄에 맞지도·쏘지도 못합니다
* **마취총은 시약·영양소 4문제 자격시험을 통과해야 열립니다.** 탄약은 비커를 검사해야 채워지고, 모둠 진도만큼 상한이 오릅니다
* **★ 1위 모둠을 「무슨 색 모자」로 실시간 공개합니다.** 그 모둠원을 마취시키면 점수가 2.5배 —
  앞서가는 모둠이 자동으로 견제받습니다
* 머리 위 닉네임, 나침반, 미니맵, 모둠 실험노트, 정답 제출, 교사용 실시간 순위·보급·학생 화면 관찰
* **⚔ 슈팅 모드** — 수업이 끝나고 남는 시간에 선생님 화면에서 켜는 **순수 슈팅 게임**.
  총·탄약·구급품을 주워 다른 분대를 쓰러뜨립니다. **학생은 스스로 켤 수 없습니다.**

## 1. 실행 (선생님 노트북)

### 준비 — 딱 한 번만 (★ 이걸 안 하면 실행이 안 됩니다)

이 게임은 **Node.js** 위에서 돌아갑니다. 노트북에 Node.js가 없으면
`start-windows.bat` 이 "Node.js 가 설치되어 있지 않습니다" 하고 멈춥니다.

**방법 A — 설치하기 (권장)**
1. [nodejs.org](https://nodejs.org) 접속 → 왼쪽 초록색 **LTS** 버튼 클릭 → `.msi` 다운로드
2. 실행 후 옵션 건드리지 말고 **[Next] 만 계속** 누르기
3. 설치가 끝나면 **컴퓨터를 한 번 재부팅** (또는 최소한 검은 창을 닫았다 다시 실행)
   — 설치 직후에는 PATH가 갱신되지 않아 여전히 "없습니다"가 뜰 수 있습니다
4. 그 다음 `start-windows.bat` 더블클릭

**방법 B — 학교 노트북이라 설치가 막혀 있다면 (관리자 권한 불필요)**
1. [nodejs.org/en/download](https://nodejs.org/en/download) 에서 **Windows / x64 / ZIP** 선택
2. 압축을 풀면 안에 `node.exe` 파일이 하나 있습니다
3. 그 `node.exe` 하나만 **이 게임 폴더 안에 복사**해 넣고 `start-windows.bat` 더블클릭
   (실행 파일이 같은 폴더의 `node.exe` 를 자동으로 찾습니다)

마지막으로 이 게임 폴더를 노트북 아무 곳에나 압축 해제해 두시면 준비 끝입니다.

> `npm install` 은 **필요 없습니다.** 외부 라이브러리를 쓰지 않도록 WebSocket 서버를 직접
> 넣어 두었고, three.js 도 `public/vendor/` 안에 들어 있어서 **인터넷 없이도** 돌아갑니다.

### 수업 시간마다
* **Windows** : `start-windows.bat` 더블클릭
* **macOS** : `start-mac.command` 더블클릭 (처음엔 우클릭 → 열기)
* 또는 터미널에서 `node server.js`

검은 창에 이렇게 뜹니다.

```
  학생 태블릿에서 아래 주소로 접속하세요 (같은 와이파이):

```

이 주소를 **칠판에 크게** 적으세요. 숫자는 노트북마다 다릅니다.
Windows 방화벽 창이 뜨면 **"액세스 허용"** 을 꼭 눌러야 합니다. (이걸 놓치면 학생이 접속 못 합니다)

#### 화면 보기가 느린 이유 — 그리고 어떻게 고쳤나 (솔직하게)

3D 화면을 한 장 뜨는 일은 **GPU가 그린 그림을 CPU로 복사**하는 작업이라, 태블릿에서는 꽤 무겁습니다.
처음 만든 방식(`toDataURL`)은 이 복사와 JPEG 압축을 **게임 루프 한가운데서 동기적으로** 처리해서,
보는 동안 학생 화면이 뚝뚝 끊겼습니다. 이렇게 바꿨습니다.

| | 이전 | 지금 |
|---|---|---|
| JPEG 압축 | `toDataURL` — 메인 스레드를 붙잡음 | `toBlob` — **비동기**, 게임을 멈추지 않음 |
| 전송 | base64 문자열을 JSON에 실음(+33%) | **WebSocket 바이너리** 그대로 |
| 속도 | 무조건 초당 2장 | **캡처에 걸린 시간을 재서 스스로 감속** (한 장 비용의 10배 간격) |
| 앱을 내려뒀을 때 | 계속 캡처 시도 | **아예 중단** |
| 앞 장이 안 끝났을 때 | 겹쳐서 또 캡처 | **건너뜀** |

측정(헤드리스 크롬, 소프트웨어 렌더링이라 실기기보다 훨씬 느린 환경):
**10.5 fps → 11.2 fps** — 관찰을 켜도 게임 프레임이 떨어지지 않았습니다.
같은 환경에서 캡처 한 장에 93ms가 걸렸고, 그래서 갱신 간격이 **자동으로 0.93초**로 늘어났습니다.

> 그래서 **화면이 뚝뚝 끊겨 보이는 것이 정상**입니다. 영상이 아니라 몇 초에 한 장씩 오는 사진이고,
> 학생 태블릿이 느릴수록 간격이 길어집니다. **학생의 게임을 지키려고 일부러 그렇게 만든 것**입니다.
> 다 보셨으면 **그만 보기**를 눌러 주세요.

## 2. 멀티플레이, 진짜 되나요? — 솔직한 답변

**구조상으로는 됩니다.** 선생님 노트북이 서버, 학생 태블릿이 클라이언트인 표준적인 LAN 게임입니다.
같은 와이파이에 있으면 브라우저만으로 접속됩니다. 다만 **학교 네트워크 설정 때문에 막힐 수 있고,
그게 유일하면서 가장 큰 변수**입니다.

### 막히는 경우 ①  AP 격리 (제일 흔함)
학교 와이파이는 보안을 위해 **기기끼리 통신을 차단**(AP isolation / 클라이언트 격리)해 두는 경우가 많습니다.
이러면 인터넷은 되는데 태블릿 → 노트북 연결만 안 됩니다.

* **미리 확인하는 법** : 수업 전에 태블릿 하나로 접속해 보세요. 5초면 됩니다.
* **해결 A** : 정보부장님께 "교실 AP의 클라이언트 격리를 꺼 달라"고 요청
* **해결 B(가장 확실)** : 선생님 **휴대폰 핫스팟**을 켜고 노트북+태블릿을 전부 거기 붙이기.
  32대는 핫스팟 동시 접속 한도(보통 10대)를 넘으니, **공유기 하나를 교실에 가져와** LAN만 쓰는 방법이 좋습니다.
  인터넷 연결이 없어도 게임은 됩니다 (외부 통신을 전혀 안 씁니다).

### 막히는 경우 ②  방화벽
Windows Defender 방화벽에서 node.exe 를 허용해야 합니다. 첫 실행 때 뜨는 창에서 허용.

### 막히는 경우 ③  주소 오타
`http://` 를 빼먹거나 `:3000` 을 빼먹는 학생이 반드시 나옵니다. 칠판에 통째로 적어 주세요.

### 성능 — 32명, 실제로 재봤습니다
`node test/load32.mjs` 로 **가상 플레이어 32명**을 동시에 접속시켜 20초간 측정한 결과입니다.

| 항목 | 측정값 |
|---|---|
| 동시 접속 | 32 / 32 성공 |
| 학생 1명당 수신 | **15.3 KB/s (약 126 kbps)** |
| 서버 총 송신 | **4.0 Mbps** |
| 서버 CPU (2코어 가상머신) | **한 자릿수 %** |
| 서버 메모리 | 약 79 MB |
| ⚔ 슈팅 모드 · **32명 전원 난사** | 1인당 **144 kbps** · 총 **4.6 Mbps** |

즉 **서버(선생님 노트북)는 전혀 부담이 안 됩니다.** 32명 × 126kbps = 4Mbps 는
가정용 공유기에도 여유로운 수준입니다. 슈팅 모드에서 전원이 기관단총을 난사해도 4.6Mbps 로,
총격 이펙트를 **150m 안에 있는 사람에게만** 보내도록 해서 통신량을 눌러 두었습니다. 병목이 생긴다면 노트북이 아니라 **교실 AP** 쪽입니다.

* 태블릿 로비에서 그래픽을 **"가볍게"** 로 두세요 (터치 기기는 자동으로 그렇게 잡힙니다).
* **다만 정직하게** — 위 32명 테스트는 *서버 부하*를 잰 것이고, 실제 **태블릿 32대의 화면 성능**은
  제 환경에서 재현할 수 없었습니다(브라우저 3대가 한계). 캐릭터를 한 명당 메쉬 7개로 줄이고
  170m 밖은 아예 안 그리도록 해 두었지만, **수업 전에 태블릿 10대 정도로 한 번은 꼭 돌려보세요.**

| 실험노트 | 🧪 버튼 | N |
| 정답제출 | ✍️ 버튼 | B |
| 자격시험 | 🎓 버튼 | — |
| 순위 | 🏆 버튼 | Tab |
| 모둠 대화 | 💬 버튼 | T |

시약은 **상자에 가까이 가면 자동 획득**됩니다 (작년 버전과 동일한 감각).

### ★ PC 마우스 — 커서를 가두지 않습니다

예전에는 화면을 한 번 클릭하면 **마우스가 잡혀 버려서**, 구급품이나 장비창을 누르려면
**ESC 를 먼저 눌러야** 했습니다. 지금은 그 잠금을 아예 쓰지 않습니다.

* **왼쪽 버튼을 누른 채 끌어야** 시점이 돌아갑니다. 떼면 멈춥니다.
* **톡 클릭 = 한 발**, **가만히 누르고 있으면(0.22초) 연사** — 연사 중에는 끌면서 쏠 수 있습니다.
* 오른쪽 버튼을 누르고 있어도 연사됩니다.
* **마우스 커서가 늘 보이므로** 화면 위 버튼(🧰 구급품 · 🎒 장비 · 🏆 순위)을 바로 누를 수 있습니다.

## 4. 게임 규칙 요약

### 시약
* 시약 1상자 = 그 시약 탄알 **6발**. 상자는 12초 후 다시 생깁니다. 섬 전체에 **115곳**.
* **종류별 최대 24발까지만** 들 수 있습니다. 가득 차면 상자를 소모하지 않고 그대로 두고
  "가득 찼습니다" 안내가 뜹니다 — 상자 앞에 눌러앉아 모으는 것이 불가능합니다.

### ★ 마취총 — 개념을 아는 학생만 쓰는 무기 (세 겹 장치)

수업에서 가장 걱정되는 장면, **"지시약을 못 외운 아이가 마취총만 들고 뛰어다니는 것"** 을 막기 위해
마취총에 세 겹의 장치를 걸어 두었습니다.

**① 자격시험 — 마취총은 처음에 잠겨 있습니다**
* 게임을 시작하면 마취탄 슬롯에 `🔒 잠김 / 시험` 이라고 뜨고 발사가 되지 않습니다.
* **자격시험은 「게임 시작」 이후에만 볼 수 있습니다.** 대기 공간에서는 🎓 버튼이 잠깁니다 —
  미리 치고 들어오는 대신 **학습지 (2)번 표를 채우고 외우는 시간**으로 쓰시라는 뜻입니다.
* 🎓 버튼 → **시약·영양소 4문제**를 풉니다. (예: "뷰렛 용액은 어떤 영양소를 검출할까요?",
  "베네딕트 용액이 양성이면 무슨 색?") 문제·보기 순서는 매번 섞이고 **정답은 서버만 압니다.**
* **4문제를 모두 맞혀야** 해금됩니다. 틀리면 **어느 문제가 틀렸는지 알려주지 않고** 20초 뒤 재응시 —
  학습지 (2)번 표를 다시 보게 만드는 장치입니다.
* 합격하면 마취탄 8발 + 15점.

**② 진도 상한 — 우리 모둠이 맞힌 비커 수만큼 화력이 늘어납니다**

| 모둠이 맞힌 비커 | 0개 | 1개 | 2개 | 3개 |
|---|---|---|---|---|
| 마취탄 보유 상한 | 8발 | 14발 | 22발 | 30발 |

* 탄약은 **비커에 시약을 명중시킬 때만** 채워집니다 — 처음 하는 (비커 × 시약) 조합에 **+3발**.
* **같은 조합을 다시 쏘면 0발** 입니다. 아무 시약이나 대충 난사해서 탄약을 벌 수 없습니다.
* 자동 회복은 30초에 1발, 그것도 8발까지만.

**③ 남용 압수**
* 비커 검사를 **한 번도 하지 않은 채** 마취탄 **6발**을 쏘면 → **45초간 총 압수**.
  화면 전체에 🚫 가 뜨고 아무것도 못 쏩니다. 4발째에 미리 경고가 나갑니다.
* 비커에 시약을 한 번 맞히면 카운터가 0으로 초기화됩니다.
* 교사 화면에서 누가 압수당했는지 보이고, 한 번에 풀어 줄 수도 있습니다(경고 카운터도 함께 초기화).

> **결과**: "외운다 → 실험한다 → 맞힌다" 를 하는 학생이 화력도 세집니다.
> 아무것도 모르는 학생은 총 자체를 못 잡고, 대충 쏘는 학생은 6발 만에 압수당합니다.

### ★ 고친 것 — "어떤 학생만 시약·불꽃이 안 잡혀요" (30명 수업 제보)

**증상**: 30명이 플레이하면 **일부 학생만** 시약 상자와 불꽃이 자동 획득되지 않음.
누가 그렇게 될지는 **매 판 랜덤**. 본인 화면에서는 멀쩡히 상자 위를 지나가는데 아무 일도 안 일어남.

**원인**: 서버의 위치 검증이 **"한 번에 18m 이상 못 움직임"** 이라는 고정값이었습니다.
그런데 태블릿 화면이 잠깐 꺼지거나 와이파이가 2초만 끊기면, 그 사이 학생은 20m 넘게 이동해 있습니다.
그러면 서버는 그 위치를 거부하고, **다음 신호는 더 멀어져 있으니 또 거부** — 이렇게 영영 갱신되지 않습니다.

```
정상 15Hz 이동        d= 0.8m  ✅
와이파이 2초 끊김      d=24.0m  ❌   ← 여기서 한 번 튕기면
그 뒤 정상으로 돌아와도 d=24.8m  ❌
                      d=25.6m  ❌   ← 차이가 계속 벌어져 영원히 복구 안 됨
```

시약 줍기도, 불꽃 점화도 **서버가 아는 위치 기준의 근접 판정**이라 둘 다 같이 죽습니다.
반면 이동·사격·비커 검사는 다른 경로라 멀쩡해 보입니다 — 그래서 "저 상자만 안 주워져요"로 보였던 것입니다.

**고친 방법** (네 겹)

1. 위치 검증을 **시간 기준**으로 변경 — "마지막 신호 이후 흐른 시간 × 달리기 속도 × 1.8 + 4m".
   2초 끊겼으면 43m까지 허용하므로 정상 복구됩니다.
2. 그래도 어긋나면 **5번째 신호에서 강제 재동기화**. 절대 방치하지 않습니다.
   (교사 화면 진행 기록에 `↻ 홍길동 위치 재동기화` 로 남아 통신 문제를 눈으로 볼 수 있습니다)
3. 시약 줍기 요청에 **학생 쪽 위치를 함께 전송** — 서버 위치가 잠깐 뒤처져 있어도 인정하고, 그 참에 맞춥니다.
4. 위치 전송을 **그림 루프와 분리된 타이머로도** 보냄 + 화면이 돌아오는 즉시 강제 전송.
   화면이 꺼져 있는 동안에도 위치가 유지됩니다.

덤으로, 프레임이 끊긴 사이 상자나 불꽃을 **뛰어넘는** 문제도 막았습니다 —
점이 아니라 **지나온 선분**으로 판정합니다.

### ★ 🏁 순위 — 음료 3개를 먼저 다 맞힌 순서

**점수가 아니라 완주 순서가 등수입니다.**

* 한 모둠이 A·B·C를 모두 맞히는 **그 순간** 등수가 확정되고, 전원에게 발표됩니다.
  > 🥇 **빨강 모자 1등 확정!** — 1모둠 · 홍길동 · 김서연 · 3분 12초 · 보너스 +150점
  > 2팀만 더 완주하면 라운드가 끝납니다
* **🥉 3등이 나오는 순간 라운드가 자동 종료**되고 결과창이 뜹니다. (`PODIUM_SIZE: 3`)
* **이미 등수를 확정한 모둠도 계속 뛰어놉니다.** 그리고 **여전히 마취탄에 맞습니다** —
  오히려 이름표에 🥇🥈 가 붙어 눈에 띄고, 잡으면 **+25점 현상금** 대상이 됩니다.
  ("1·2등 했으니 3등 나올 때까지 놀아라")
* 완주하지 못한 모둠은 그 뒤로 **진행률**(맞힌 비커 → 검사한 조합 수 → 점수) 순으로 정렬됩니다.
* 확정 보너스 : 1등 +150 / 2등 +100 / 3등 +60 (`SCORE_FINISH`). 점수와 등수가 대체로 일치하도록 넣은 값이며,
  **어긋나더라도 등수는 완주 순서가 우선**입니다.

### ★ 👑 선두 모둠 공개 — 마취총에 '이유'를 만들어 주는 장치

마취총이 단순한 장난이 되지 않게, **쏠 이유**를 만들었습니다.

* 라운드 시작 **60초 뒤부터 45초마다**, **아직 완주하지 못한 모둠 중** 진행률 1위를 **전원에게 알립니다.**
  (이미 등수를 확정한 모둠은 👑 대신 🥇🥈 가 붙고, 역시 표적입니다)
  아이들은 서로 "몇 모둠"인지 모르므로 **모자(헬멧) 색**으로 부릅니다.

  > 👑 1위는 **빨강 모자** — 1모둠
  > 2반 홍길동 · 2반 김서연 · 비커 1/3 · 검사 7/12 · 마취시키면 **+25점**

* **닉네임도 같이** 알려 주므로 이름표를 보고 바로 찾을 수 있습니다.
* 화면 왼쪽 위에 **작은 칩이 항상 떠 있어** 지금 1위가 무슨 색인지 언제든 확인됩니다.
* 1위 모둠원의 **이름표에 👑 이 붙고 금색으로 바뀝니다.** 멀리서도 표적이 보입니다.
* **1위 모둠원을 마취시키면 +25점** (보통 마취는 +10점).
* 1위 본인들에게는 **"우리가 1위입니다 — 다른 모둠이 노립니다"** 라고 알려 주고,
  안전구역(창고)을 쓰라고 안내합니다.

**순위 기준**은 점수가 아니라 **진행률**입니다 — ① 맞힌 비커 수 → ② 검사한 (비커×시약) 조합 수 → ③ 점수.
즉 **실험을 많이 한 모둠이 표적이 됩니다.** 마취만 해서 1위가 될 수는 없습니다.

> **의도한 효과**
> * 한 모둠이 독주하지 못합니다 (앞설수록 견제받음 = 자동 난이도 조절).
> * "총을 왜 쏘지?" 가 "저 빨강 모자 잡아야 해!" 로 바뀝니다.
> * 1위는 쫓기면서 실험해야 하므로 **안전구역과 창고 옥상을 실제로 활용**하게 됩니다.
>
> ⚠️ 다만 **남용 압수 규칙은 그대로 작동합니다.** 비커 검사를 한 번도 안 한 채 마취탄만 6발 쏘면
> 45초간 총을 압수당합니다. 즉 **1위를 사냥하려면 자기도 실험을 해야 합니다.** 의도된 설계입니다.
>
> 끄고 싶으시면 `gamedata.js` 의 `LEADER_ANNOUNCE: false`.
> 발표 주기는 `LEADER_ANNOUNCE_SECONDS`, 현상금은 `SCORE_TRANQ_LEADER`.

**모자 색 이름** (`TEAM_COLOR_NAMES`) — 칠판에 적어 두시면 좋습니다.

| 모둠 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| 모자 | 빨강 | 파랑 | 초록 | 노랑 | 보라 | 민트 | 분홍 | 회색 |

### ★ 🔥 가열 — 베네딕트만 다르게 만든 이유

교과서에서 베네딕트 반응은 **"가열"이 조건**입니다. 말로만 외우면 시험 끝나고 사라지는 지식이라,
게임 안에서 **몸으로 겪게** 만들었습니다.

* 섬 곳곳에 **가열대(모닥불) 24곳**이 있습니다. 비커마다 **19m 거리에 2개씩**, 나머지는 야드와 벌판에.
  미니맵에 **주황색 삼각형**으로 표시되고, 멀리서도 주황 기둥이 보입니다.
* 불에서 **4.6m 안**에 들어가면 **몸에 불이 붙습니다**(캐릭터 머리 위에서 불꽃이 타오릅니다 —
  다른 학생 화면에서도 보입니다). 지속 시간은 **25초**입니다.
  화면 **왼쪽**에 「🔥 몸에 불이 붙었습니다 — 베네딕트 발사 가능」 이라고만 뜹니다.
  **남은 초는 일부러 표시하지 않습니다** — 예전에는 이 배지가 화면 가운데 위에 있어서
  **시약 반응 결과 알림을 가렸습니다.** 불이 붙었는지 여부만 보이면 판단에 충분합니다.
* **가열된 상태에서 쏜 베네딕트만 반응합니다.** 식은 채로 쏘면
  「🔥 가열해야 일어납니다 — 가장 가까운 불꽃까지 ○m」 안내가 뜨고 **아무 일도 일어나지 않습니다.**
* 중요한 설계: 식은 상태의 사격은 **음성(－)으로도 기록되지 않습니다.**
  거짓 음성을 실험노트에 남기면 아이들이 **틀리게 배우기** 때문입니다.
* 나머지 세 시약(아이오딘·뷰렛·수단Ⅲ)은 **가열 없이 그대로** 반응합니다.

> 수업 효과: "불 → 뛰어가서 베네딕트" 라는 동선이 생기고, **베네딕트만 왜 다른가**를
> 학습지 (5)-③에서 묻습니다. 불이 붙은 친구가 보이면 근처에 가열대가 있다는 신호이기도 합니다.
>
> 손잡이는 `gamedata.js` : `HEAT_SECONDS`(25) · `HEAT_RADIUS`(4.6).
> 가열 규칙을 아예 끄려면 `REAGENTS.benedict` 의 `needsHeat: true` 줄을 지우세요.

### ★ 대기 공간 · 모둠 창고 · 안전구역

**① 대기 공간 (접속하면 여기부터)**
* 섬 바깥의 별도 연습장입니다. 발판(0.8 / 1.7 / 2.6 / 3.0m), 낮은 통로(앉기 연습), 과녁 3개가 있습니다.
* **탄약이 줄지 않고, 서로 맞지도 않습니다.** 조작만 익히는 곳입니다.
* 밖으로 나갈 수 없고, 화면 위에 「선생님이 시작하기를 기다리는 중」 배너가 떠 있습니다.
* 32명이 다 들어올 때까지 먼저 온 학생이 혼자 게임을 시작해 버리는 일이 없습니다.

**② 모둠 창고 8동 (섬 가장자리, 모둠마다 하나씩)**
* 30m × 24m · 높이 7.6m. **출입구는 섬 중심 쪽**을 향하고, 외벽에 **모둠 색 띠**가 둘러져 있어 멀리서도 찾습니다.
* 안쪽 벽을 따라 **계단 15칸**이 옥상까지 이어집니다. 점프 없이 걸어서 올라갑니다.
  (옥상은 난간이 있고, 계단 위쪽은 천장을 뚫어 두어 머리가 걸리지 않습니다.)
* 옥상에서는 섬이 넓게 보입니다 — 비커 위치와 사람 몰린 곳을 확인하기 좋습니다.
* 안에는 엄폐용 실험대 2개가 있습니다.

**③ 안전구역 = 창고 안 (반지름 26m)**
* **정답 제출은 안전구역 안에서만** 됩니다. 밖에서는 제출 버튼이 아예 잠기고
  「안전구역(모둠 창고)에서만 제출할 수 있습니다」 안내가 뜹니다.
* 안전구역 안에서는 **마취탄에 맞지 않고, 쏠 수도 없습니다.** 모둠끼리 안심하고 상의하는 공간입니다.
* **다른 모둠 창고에 들어가도 제출은 됩니다.** 반대편에서 실험하다 급하면 가까운 창고로 뛰어들면 됩니다.
* 화면에 **🛡 안전구역** 배지가 뜨고, 미니맵에도 8개 창고가 모둠 색 원으로 표시됩니다.

> 수업 운영 관점: "실험은 밖에서, 결론은 안에서" 라는 리듬이 생깁니다.
> 창고 안이 총이 안 통하는 곳이라 **모둠 회의가 실제로 일어납니다.**

### 정답 제출
* **A·B·C를 한 화면에서 골라 한 번에 제출**합니다. 이미 맞힌 비커는 자동으로 건너뜁니다.
* 제출하면 **제출지가 닫히고** 채점 결과창이 뜹니다 — 비커별로 ✅정답 / ❌오답, 맞힌 것은 음료 이름 공개.
* 화면 왼쪽 위에 **A ✅ B ❌ C ⬜** 현황이 항상 떠 있습니다.
* **채점 자체는 즉시입니다** (실측 왕복 약 0.2초). 예전에 "채점이 오래 걸린다"고 느껴진 것은
  계산이 느려서가 아니라 **틀렸을 때 모둠 전체가 30초 동안 잠겼기 때문**이었습니다.
* 이제 오답 대기는 **4초 → 8초 → 15초 → 25초**로 **틀릴수록 길어집니다.**
  한 번 실수는 거의 바로 다시 제출할 수 있고, **계속 찍는 모둠만** 점점 오래 기다립니다.
  맞히면 대기 단계는 **처음(4초)으로 초기화**됩니다.
* 대기 중에는 제출 버튼에 **「⏳ 3초 후 다시 제출」** 처럼 남은 시간이 **실시간으로 줄어듭니다.**
  멈춘 게 아니라 기다리는 중이라는 걸 학생이 바로 알 수 있습니다.
* 틀린 것의 정답은 알려주지 않습니다.

### ★ 색 반응은 '우리 모둠에게만' 보입니다
32명이 비커 몇 개에 번갈아 쏘면 **남이 일으킨 반응 때문에 내 결과를 착각**하게 됩니다.
그래서 색 반응과 결과 기록은 **쏜 사람의 모둠에게만** 전달됩니다.
다른 모둠은 총성과 탄도만 볼 뿐, 비커 색은 그대로 보입니다.

모둠원끼리 연달아 쏠 때도 헷갈리지 않도록, 비커 위에
**「뷰렛 → 보라색 / 홍길동 · 양성 ＋」** 같은 결과판이 7초간 떠 있습니다.
누가 무슨 시약을 쐈고 결과가 무엇인지 항상 명확합니다.

### 기타
* 마취탄 3발 → **30초** 마취. 25초 동안 안 맞으면 누적이 1 줄어듭니다. **같은 모둠끼리는 안 맞습니다.**
* 점수 : 비커 검사 +5 / 시약 4종 수집 +20 / 자격시험 합격 +15 / 상대 마취 +10 /
  **👑 선두 모둠원 마취 +25** / **정답 +100** / 오답 −20
* 한 라운드 15분. **3등이 나오면 즉시 종료**되고 정답과 순위가 공개됩니다.

### 이동
| | 속도 |
|---|---|
| 걷기 | 6.6 m/s |
| 달리기 (조이스틱 끝까지 / Shift) | 12 m/s |
| **앉기** | **1.7 m/s** — 달리기의 14%. 앉으면 달릴 수도, 점프할 수도 없습니다 |
| 점프 | 최고 **3.0 m** — 컨테이너 한 단 위로 올라갈 수 있습니다 |

앉으면 캐릭터가 눈에 띄게 주저앉고 무릎을 접습니다(다른 학생 화면에서도 보입니다). 엄폐·잠복용입니다.

## 5. 과학 내용 — 꼭 확인해 주세요

`public/js/gamedata.js` 파일 하나만 고치면 됩니다. 다른 파일은 건드릴 필요 없습니다.

**음료는 24종**이고, 검출 패턴은 **10가지**입니다. 라운드마다 여기서 8종만 뽑아 씁니다.

| 검출 패턴 | 같은 패턴의 음료들 |
|---|---|
| 지방만 | 식용유 · 참기름 · 올리브유 |
| 4가지 모두 음성 | 물 · 제로 사이다 · 보리차 · 탄산수 |
| 단백질만 | 난백(달걀 흰자) |
| 단백질 · 지방 | 우유 · 두유 · 달걀 노른자 · 생크림 · 두부 간 물 |
| 녹말만 | 쌀뜨물 · 녹말물 · 감자 간 물 |
| 당류만 | 오렌지 주스 · 사이다 · 이온음료 · 꿀물 |
| 녹말 · 당류 | 식혜 |
| 녹말 · 단백질 | 미숫가루 물 |
| 당류 · 지방 | 커피믹스 |
| 당류 · 단백질 | 마시는 요구르트 |

### 실제 실험과 다를 수 있는 두 지점 (선생님 판단이 필요합니다)

1. **커피믹스의 당류** — 커피믹스의 단맛은 대부분 **자당(설탕)** 이고, 자당은 **비환원당**이라
   실제 베네딕트 반응은 **음성**으로 나올 수 있습니다. 실험과 게임 결과를 일치시키시려면
   `gamedata.js` 의 `coffee` 항목에서 `'sugar'` 를 지우세요.
2. **우유의 당류** — 요청하신 대로 우유는 **교과서 기준(단백질 + 지방)** 으로 두었습니다.
   실제 우유의 유당은 환원당이라 진짜 실험에서는 베네딕트 **양성**이 나올 수 있으니,
   실험 결과와 맞추시려면 `milk` 의 `has` 에 `'sugar'` 를 다시 넣으세요.

또, **물 · 제로 사이다 · 보리차 · 탄산수는 4가지 시약에 모두 음성**이라 이 방법만으로는
서로 구별할 수 없습니다. 같은 이유로 **우유와 두유**, **식용유와 참기름**도 검사만으로는 못 가립니다.
그래서 서버가 **한 라운드 후보 안에는 같은 패턴의 음료를 하나만** 넣습니다.
즉 **문제가 항상 풀립니다**(테스트 `rounds.mjs` 가 매 라운드 검사합니다).
"같은 결과가 나오는 음료가 여럿 있다"는 사실 자체는 학습지 (5)-① 문항의 소재로 남겨 두었습니다.

### ★ 라운드마다 음료가 새로 뽑힙니다 (외우기 방지)
한 시간에 3판을 돌리시는데 예전에는 음료가 8종뿐이라 **2판째부터 답을 외워 버렸습니다.**
지금은 이렇게 바뀌었습니다.

* 전체 **24종** 중에서 라운드마다 **후보 8종**을 새로 뽑습니다.
* **이미 정답으로 나온 음료는 뒤로 밀려서** 다음 라운드 정답이 되지 않습니다 (3판 내내 안 겹칩니다).
* 같은 패턴에 음료가 여러 개라, **"단백질＋지방＝우유"** 식으로 외워 두면 오히려 틀립니다
  (이번 판엔 두유나 생크림일 수 있으니까요). **검사 결과 + 후보 목록**을 같이 봐야 답이 나옵니다.

### 음료 후보는 보여 주고, 답은 안 알려 줍니다
학생 **실험노트 아래**에 **이번 라운드 후보 8종**의 이름이 그대로 나옵니다 (무엇 중에서 고르는지
알아야 추리를 시작할 수 있으니까요). 전체 24종을 다 보여 주지는 않습니다.
다만 **어떤 음료가 무슨 영양소를 가졌는지는 안 알려 줍니다.**
후보를 자동으로 좁혀 주던 '힌트' 버튼은 **삭제**했습니다 — 추리가 곧 학습 목표이므로.

선생님 화면에도 같은 8종이 뜨고, 거기에는 **무반응 음료 표시**가 붙어 있어
어떤 조합이 나올 수 있는지 한눈에 보입니다.

> 손잡이는 `gamedata.js` : `DRINKS` 배열(음료 추가/삭제) · `ROUND_CANDIDATES`(8, 후보 개수).
> 음료를 더 넣으실 때는 `has` 에 `starch / sugar / protein / fat` 중 해당하는 것만 적으면 됩니다.

## 5-B. ⚔ 슈팅 모드 — 남는 시간용 (수업 내용과 무관)

수업이 일찍 끝났을 때, **선생님 화면 [⚔ 슈팅 모드]** 카드에서 켜는 별도 모드입니다.
시약·비커·자격시험·안전구역이 **전부 사라지고**, 배틀그라운드식 순수 슈팅 게임이 됩니다.
**학생은 이 모드를 스스로 켤 수 없습니다** (서버가 교사 화면에서 온 명령만 받습니다).

### 켜는 순서 (버튼 2개)

| 버튼 | 하는 일 |
|---|---|
| **① ⚔ 슈팅 모드 켜기** | 전원이 **로비(대기 공간)** 로 모이고, 화면에 **분대 만들기** 창이 뜹니다 |
| **② ▶ 슈팅 시작 — 5분** | 5초 카운트다운 뒤 **섬 곳곳에 흩어져** 출발 |
| 🏁 지금 끝내기 | 시간 전에 끊고 순위 정산 |
| 🧪 실험 모드로 돌아가기 | 원래 수업 화면으로 복귀 (전원 대기 공간) |

**실험 기록은 그대로 남습니다.** 슈팅을 하고 [실험 모드로 돌아가기] → [게임 시작]을 누르면
평소처럼 새 라운드가 돌아갑니다.

### 분대 — 혼자도 되고, 최대 3명

* 로비에서 **친구 분대의 [합류] 버튼**을 누르면 같이 뜁니다. **아무것도 안 하면 혼자**입니다.
* 같은 분대끼리는 **총이 안 맞습니다.** 이름표가 **초록(아군) / 빨강(적)** 으로 구분되고,
  모자 색이 분대 색입니다.
* 순위는 **분대 전체 킬 수** (같으면 덜 쓰러진 분대가 위).

### 총 · 탄약 · 구급품

땅에 세 종류의 상자가 떨어져 있고, **가까이 가면 자동으로 줍습니다**(22초 뒤 다시 채워집니다).

| 총 | 데미지 | 연사 | 탄창 | 사거리 | 반동 | 최대 배율 |
|---|---|---|---|---|---|---|
| 권총 (기본 지급) | 24 | 보통 | 12 | 60m | 0.011 | 1.8× |
| 기관단총 | 15 | 매우 빠름 | 30 | 48m | **0.0035** | 1.8× |
| 샷건 | 68 (가까울수록 셈) | 느림 | 5 | 20m | 0.020 | 1.5× |
| 돌격소총 | 26 | 빠름 | 30 | 88m | 0.006 | 2.4× |
| 저격총 | 92 | 매우 느림 | 5 | 160m | 0.028 | **6× 🔭** |

### 🎒 장비창 — 주운 총을 골라서 낀다

* 주운 총은 **가방(최대 4자루)** 에 쌓입니다. 아무것도 버려지지 않습니다.
* **🎒 장비 버튼(또는 G 키)** 을 누르면 가진 총이 나오고, **[장착] / [버리기]** 를 눌러 바꿉니다.
  **숫자키 1~4** 로도 바로 바꿀 수 있습니다.
* 편의상 **지금 든 것보다 좋은 총을 주우면 바로 장착**되고, 나쁜 총은 가방에만 들어갑니다.
  (달려가다 저격총이 권총으로 바뀌는 사고는 없습니다.)
* 이미 가진 총을 또 주우면 **탄약만** 챙깁니다. 마지막 한 자루는 버릴 수 없습니다.
* 탄창을 다 쓰면 **자동으로 재장전**됩니다. 따로 누를 버튼이 없습니다.

### 🔭 조준경 — 두 손가락으로 벌리면 당겨집니다

* 태블릿에서 **두 손가락으로 벌리면 확대**, 오므리면 축소. PC는 **마우스 휠**.
* **저격총(6배)** 은 확대하면 검은 원형 조준경이 뜨고 **1인칭(눈높이)** 으로 붙습니다.
  다른 총도 조금(1.5~2.4배)은 당겨집니다.
* 당길수록 **조준 감도가 자동으로 낮아져서** 손 떨림이 줄어듭니다.
* 총을 바꾸거나 쓰러지면 배율은 원래대로 돌아옵니다.

### 반동

**★ 수업 피드백으로 전체적으로 크게 낮췄고, 특히 기관단총은 0.022 → 0.0035 (약 1/6)** 로 줄였습니다.
한 발마다 화면이 살짝 튀지만 **초당 0.55라디안 속도로 저절로 제자리로 돌아오기 때문에**,
기관단총을 한 탄창(30발) 다 비워도 조준점이 하늘로 올라가지 않습니다
(측정: 20발 연사 후 최대 0.004 rad ≈ 0.2°). 앉으면 반동이 추가로 40% 줄어듭니다.
* 📦 탄약 상자 +50발 · 🧰 구급품은 체력 +45 (최대 3개 소지, 🧰 버튼 또는 `H` 키).
* 총 바꾸기 `1~4` · 장비창 `G` · 구급품 `H`.
* 체력 100. **쓰러지면 10초 뒤 자동 부활**합니다 — 한 번 죽어도 끝까지 놉니다.
  부활하면 **권총부터 다시** 시작하므로 좋은 총을 또 주우러 가야 합니다.

### 자기장 (5분)

미니맵의 **흰 원 안이 안전지대**, 점선은 다음에 줄어들 크기입니다.
45초 → 120초 → 185초 → 240초에 네 번 좁아지고, 밖에 있으면 **1초마다 체력이 깎입니다**
(2 → 4 → 6 → 9). 넓은 섬에서 서로 못 만나고 끝나는 일을 막는 장치입니다.

> 조절 손잡이는 `public/js/battledata.js` 한 파일에 전부 있습니다 —
> `BATTLE.SECONDS`(판 길이) · `RESPAWN_SECONDS`(부활 대기) · `SQUAD_MAX`(분대 인원) ·
> `BAG_SIZE`(가방 칸) · `GUNS`(총 성능·반동·배율) · `RECOIL_RECOVER`(반동 회복 속도) ·
> `BATTLE.ZONE`(자기장 일정).
> 시간이 짧으면 `SECONDS: 300` 을 180 정도로 줄이세요.
> 반동이 여전히 세면 `GUNS.○○.recoil` 을 더 낮추거나 `RECOIL_RECOVER` 를 올리세요.

| 30–40분 | 교사 화면에서 **새 라운드** → 음료 후보와 정답이 통째로 바뀝니다 (2회차) |
| 40–45분 | 학습지 (5) 생각해 보기 정리 |
| (남는 시간) | 교사 화면 **⚔ 슈팅 모드 켜기 → ▶ 슈팅 시작** (5분) · 끝나면 **실험 모드로 돌아가기** |

**팁**
* 모둠 번호는 **미리 정해서** 칠판에 붙여 두세요. 로비에서 학생이 직접 고릅니다.
  아무거나 고르면 4명씩 자동 배정됩니다.
* 라운드마다 (A)(B)(C)가 **24종에서 새로 뽑히고 지난 판 정답은 제외**되므로,
  3판을 연달아 하셔도 **답을 외워서 넘기지 못합니다.**
* 마취탄이 너무 시끄러우면 `gamedata.js` 의 `TRANQ_MAX_AMMO` 를 30 → 8 정도로 줄이세요.

## 7. 검증한 것 / 검증 못 한 것

`node test/smoke.mjs` 로 헤드리스 크롬 3대를 실제로 접속시켜 확인했습니다.

**통과 확인**
* 3명 동시 접속, 서로 캐릭터·닉네임이 보임
* 서버를 통한 위치 동기화 (스냅샷 보간)
* 이동 · 지형/컨테이너 충돌
* 시약 상자에 걸어가면 자동 획득 (4종 전부)
* 비커 3개 × 시약 4종 = 12번 사격 → **검출 결과가 음료 성분 데이터와 100% 일치**
* 마취탄 3발 → 마취 / 마취 중 이동 불가 / **같은 모둠에게는 안 통함**
* 오답 −20점 + 쿨다운(4 → 8 → 15 → 25초로 증가)
* 서버 위치 검증(순간이동 치트 차단)이 실제로 작동
* 자바스크립트 오류 0건

`node test/waitflow.mjs` — **대기 공간 · 동시 시작 · 안전구역** (브라우저 3대, 18항목 전부 통과)

* 접속하면 대기 공간에서 시작하고 **밖으로 못 나감**
* 대기 중 연습 사격은 **탄약이 줄지 않음**
* 선생님이 시작 → 5초 카운트다운, **카운트다운 중에는 이동 불가**
* **같은 모둠은 같은 창고, 다른 모둠은 다른 창고**, 전원이 안전구역 안에 리스폰
* 안전구역 안 → 정답 제출됨 / **밖 → 제출 거부 + 버튼 잠김**
* **창고 안에 있는 상대는 마취탄에 맞지 않음**

`node test/heat.mjs` — **🔥 가열 규칙 + 자격시험 응시 시점** (11항목 전부 통과)

* 대기 공간에서는 자격시험 패널이 안 열리고, **서버도 문제 발급을 거부**
* 필드에 가열대 24곳, 비커에서 달려갈 수 있는 거리
* **식은 채로 쏜 베네딕트 → 반응 없음 + 안내, 실험노트에 기록도 안 남음**
* **불에 다가가면 몸에 불이 붙고**, 그 상태로 쏜 베네딕트는 반응 (결과가 음료 성분과 일치)
* 아이오딘은 가열 없이도 그대로 반응
* 게임이 시작되면 자격시험 응시 가능

`node test/sync.mjs` — **★ "어떤 학생만 시약·불꽃이 안 잡힌다" 버그 재발 방지** (6항목 전부 통과)

통신을 일부러 끊고 100m 넘게 이동시킨 뒤에도 불꽃이 붙고 시약이 주워지는지,
화면(rAF)이 멈춰도 위치 전송이 계속되는지 확인합니다.
**고치기 전 코드로 되돌리면 이 테스트는 실제로 실패합니다** — 그 버그를 정확히 잡고 있다는 뜻입니다.

`node test/podium.mjs` — **🏁 완주 순서 순위 + 3등 자동 종료** (17항목 전부 통과)

* 1등 확정이 모자 색과 함께 전원에게 발표됨 · 1등만 나왔을 땐 라운드 계속
* **이미 1등한 모둠도 마취탄에 맞고, 현상금(+25점) 대상**
* 마취 30초
* **3등이 나오면 자동 종료** · 결과가 🥇🥈🥉 완주 순서로 정산 · 미완주 모둠은 그 뒤

`node test/leader.mjs` — **👑 선두 모둠 공개 + 마취 현상금** (12항목 전부 통과)

* 라운드 시작 직후에는 발표하지 않음(다 0점)
* 진행률이 앞선 모둠이 선두로 지목됨
* **발표에 「모자 색」이 들어감** · **닉네임도 같이** 나옴 · 현상금 점수도 안내
* 상시 표시 칩 · 선두 본인에게는 "표적이 되었다" 안내
* 선두 모둠원 이름표에 👑 이 붙음
* **선두를 마취시키면 +25점** (보통 +10점)

`node test/rounds.mjs` — **★ 채점 속도 · 가열 표시 · 음료 중복 방지** (17항목 전부 통과)

* **채점 자체는 즉시** — 실측 왕복 **214ms** (느린 건 계산이 아니라 오답 대기였음을 수치로 확인)
* 첫 오답 대기 **4초**(예전 30초) · 제출 버튼의 남은 시간이 **실제로 줄어듦**
* **계속 찍으면 대기가 길어짐** (1회 4초 → 2회 8초)
* **가열 배지가 시약 반응 알림과 화면에서 겹치지 않음** (좌표로 검사) · 배지에 **남은 초가 없음**
* 음료 **24종 / 패턴 10가지** · 같은 패턴 음료가 여럿 존재(외우기 방지)
* **★ 후보 안에 구분 불가능한 조합이 없음 = 문제가 반드시 풀림**
* **★ 3라운드 연속으로 정답 음료가 겹치지 않음** · 새 라운드에서 후보도 바뀜

`node test/battle.mjs` — **⚔ 슈팅 모드** (25항목 전부 통과, 브라우저 3대)

* **★ 학생이 보낸 슈팅 모드 요청은 서버가 무시** (교사 화면에서만 켜짐)
* 켜면 실험 UI 가 사라지고 체력·총 HUD 가 뜸 · 분대 만들기 창 자동 표시
* **분대 합류(최대 3명)** · 시작하면 섬으로 흩어짐
* **총기 상자 = 더 좋은 총일 때만 교체** / 나쁜 총(권총)으로는 안 바뀜
* 발사 → 탄창 감소 → **탄창을 다 쓰면 자동 재장전**
* 사격 → 체력 감소 → 처치 → **10초 뒤 자동 부활(체력 가득)**
* **같은 분대끼리는 안 맞음** · 구급품으로 체력 회복
* **자기장 밖이면 체력이 계속 깎임** · 끝내면 분대 킬 순위 정산
* **★ 실험 모드로 깨끗하게 복귀** — 되돌린 뒤 실험 라운드가 정상 작동

`node test/gear.mjs` — **🎒 장비창 · 🔭 조준경 · 반동 · PC 마우스** (24항목 전부 통과)

* **★ 화면을 클릭해도 마우스가 잡히지 않는다** (ESC 없이 버튼을 바로 누를 수 있음)
* **★ 왼쪽 버튼을 누른 채 끌어야** 시점이 돌아가고, 떼면 멈춘다
* 구급품 버튼 클릭이 서버까지 도달하고, **그 클릭으로 시점이 돌아가지 않는다**
* **★ 기관단총 20발 연사 후 화면이 0.004rad(0.2°)만 올라감** — 예전엔 하늘을 봤다
* 튄 화면이 저절로 제자리로 돌아온다
* **★ 주운 총이 가방에 쌓이고**, 장비창에서 **클릭 한 번으로 장착 / 버리기**
* 마지막 한 자루는 버려지지 않는다
* **★ 휠(=두 손가락 벌리기)로 6배 확대**, 저격 조준경 화면이 뜨고 1인칭으로 붙는다
* 다시 오므리면 원래대로 · **총마다 최대 배율이 다르다**

`node test/watchperf.mjs` — **학생 화면 보기** (10항목 전부 통과)

* 교사 화면에서 **이름을 클릭**하면 실제로 화면이 뜨고 "불러오는 중"이 사라짐
* **관찰 중에도 학생 프레임이 안 떨어짐** (10.5 → 11.2 fps)
* 캡처 비용을 재서 간격을 자동 조절 · 계속 갱신됨 · 그만 보면 송출 중단

`node test/stairs.mjs [모둠번호]` — **창고 계단 → 옥상**을 텔레포트 없이 *실제로 걸어서* 검증
(출입구 방향이 다른 1모둠·2모둠 두 형태 모두 통과: 바닥 → 계단 15칸 → 옥상 슬래브,
옥상에서 뛰어다녀도 밖으로 튕겨 나가지 않음)
